## 二、修复要点详解

### H-01 JZT 业务类 PIN_ID 动态化

```python
# 修复前（main.py:3881 等 5 处）
PIN_ID = "FYA8888"

# 修复后
@property
def PIN_ID(self) -> str:
    from runtime_config import get_shop_pin
    return get_shop_pin()
```

**效果**：MIYO/OTA 跑 JZT 全链路，自动读取对应店铺 pin（miyo-周 / ota8888），不再带错 PIN。

### H-02 SHOP_NAME 函数式读取

```python
# 修复前（main.py:62）
SHOP_NAME = "FYA8888"

# 修复后
def SHOP_NAME() -> str:
    return runtime_config.get_shop_name_display()
```

**效果**：CLI banner 不再永远显示 FYA，三店运行显示各自店名。

### H-03 DB schema 多店隔离

```sql
-- 修复前
CREATE TABLE biz_xxx (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    report_date TEXT NOT NULL,
    etl_time TEXT NOT NULL,
    ...
    UNIQUE(report_date, 主键列)
);

-- 修复后
CREATE TABLE biz_xxx (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    shop_pin TEXT NOT NULL,        -- 新增
    stat_date TEXT NOT NULL,        -- 新增（独立列方便 MySQL 索引）
    report_date TEXT NOT NULL,
    etl_time TEXT NOT NULL,
    ...
    UNIQUE(shop_pin, stat_date, 主键列)  -- 联合唯一键
);
```

**效果**：
- 多店并发跑同一业务，A 店 DELETE 只删 A 店数据
- MySQL 迁移时直接对应 `UNIQUE KEY (shop_pin, stat_date)`

## 三、运行时配置加载器（runtime_config.py）API

| 函数 | 数据源优先级 | 缺失行为 |
|------|--------------|----------|
| `get_shop_id()` | `os.environ["SHOP_ID"]` | SystemExit(3) |
| `get_shop_pin()` | `SHOP_PIN` → config.xlsx「店铺账号」 | SystemExit(3) |
| `get_app_id(biz)` | `APP_ID_<BIZ>` → `APP_ID` → config.xlsx「京麦接口/app_id_<biz>」 | SystemExit(3) |

| `get_shop_name_display()` | `get_shop_id()` 同源 | SystemExit(3) |
