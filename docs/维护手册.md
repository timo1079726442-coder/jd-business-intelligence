## 二、自动检测（推荐）

### 2.1 跑一次完整检测

```bash
python maintain.py
```

输出示例（2026-08-11 实测）：
```
🟢 全部正常，可放心使用
  ✅ 正常: 7
  ⚠️ 警告: 0
  ❌ 错误: 0
```

### 2.2 检测项分类

| 检测类型 | 命令 | 含义 |
|---|---|---|
| 仅 Cookie | `python maintain.py --only cookies` | 检查 3 个 Cookie 文件存在 + 关键字段 + 实测可达 |
| 仅 IMAP | `python maintain.py --only imap` | 检查 imap_config.ini + 用授权码登录 IMAP |
| 仅 URL | `python maintain.py --only urls` | 检查 3 个京东端点 GET 可达 |
| 静默模式 | `python maintain.py --quiet` | 只输出汇总，适合定时任务/CI |
| JSON 输出 | `python maintain.py --json` | 输出 JSON 报告，便于外部脚本消费 |
| 实测 Cookie | `python maintain.py --live` | 用 Cookie 访问真实 GET 端点验证（**会发真实请求**） |

### 2.3 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 全部正常 |
| 1 | 发现 P0 过期项，需立即处理 |
| 2 | 脚本执行异常 |

适合接 CI / 定时任务：
```bash
python maintain.py --quiet || echo "❌ 维护检测失败"
```

### 2.4 推荐定时任务（cron / 计划任务）

| 频率 | 命令 | 场景 |
|---|---|---|
| 每天早上 8 点 | `python maintain.py --quiet` | 检查 Cookie 是否过期 |
| 每周日早上 | `python maintain.py --live` | 周末深度检查（实测 Cookie 可达） |
| 每次跑业务前 | `python maintain.py --quiet` | 兜底自检 |

## 三、手动抓取流程（按项）

### 3.1 🔴 京麦 .shop.jd.com Cookie（项目14）

**抓取工具**：浏览器 F12 / 影刀 RPA

**手动步骤**：
1. Chrome / Edge 打开 `https://shop.jd.com/jdm/trade/tools/export/ExprotList`
2. 确保已登录（右上角显示 `FYA8888`）
3. F12 → Network → 勾选「Preserve log」 → 刷新页面 → 找任意一个 sff.jd.com / export.shop.jd.com / shop.jd.com 域请求
4. 右键 → Copy → Copy as cURL (bash) → 看 Cookie 头内容
5. 把整个 Cookie 字符串写到 `config/jm_cookie.txt`
6. 验证：`python maintain.py --only cookies` → 应显示 ✅

**关键字段**（缺失即不通过）：
- `3AB9D23F7A4B3CSS=...`（dsm-eid 提取源）
- `pin=FYA8888`（账号标识）
- `thor=...`（会话令牌）
- `flash=...`（长会话密钥，最重要）

### 3.2 🔴 京麦 h5st（项目14）

**抓取工具**：浏览器 F12 / 影刀 RPA

**手动步骤**：
1. Chrome / Edge 打开 `https://shop.jd.com/jdm/trade/tools/export/ExprotList`
2. 在「订单明细【加密】导出」区域，**手动新建一个导出任务**（选日期 → 点「导出」按钮）
3. F12 → Network → 勾选「Preserve log」
4. 找到 `createdExportTask` POST 请求（URL 含 `createdExportTask`）
5. 看 Request Headers → 找 `h5st` 字段（值约 1100+ 字符，以 `2026...` 开头）
6. **复制整个 h5st 值**（每次新建任务前都要抓，5-30 分钟过期）
7. 命令行：`python main.py --biz_key "京麦订单明细_完整一键导出" --date 2026-08-10 --h5st "<h5st>"`

**关键字段**（缺失即不通过）：
- `h5st: 20...;...;tk03wdb141c7918njg1fp...;...;5.3;...;q3Ep...;...;pjLO-HkS8ilgHGnP7mlgCqUT`
- 长度约 1100 字符
- 包含 `tk03wdb141c7918njg1fp`（账号指纹）
- 必须每次新建任务前抓一次，**禁止复用**

### 3.3 🔴 QQ 邮箱 IMAP 授权码（项目14）

**抓取工具**：QQ 邮箱网页版

**手动步骤**：
1. 浏览器打开 `https://mail.qq.com/`
2. 登录（用户：`1079726442@qq.com`）
3. 顶部「设置」→「账户」→ 滚到「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务」
4. 开启「IMAP/SMTP服务」→ 验证密保 → 复制生成的 16 位授权码
5. 把授权码写到 `config/imap_config.ini` 的 `auth_code` 字段
6. 验证：`python maintain.py --only imap` → 应显示 ✅

**关键字段**：
- `auth_code: 16位字符串`（不是 QQ 密码）
- `user: 1079726442@qq.com`（固定）
- `host: imap.qq.com`（固定）
- `port: 993`（固定 SSL）

### 3.6 🟡 风控签名盐值（项目1/4/5/6/13）

**过期周期**：不定期（京东服务端变更会更新）

**症状**：所有商智业务返回 `status=-407` 或 `{"code": -402, "msg": "不安全的请求"}`

**抓取流程**：
1. 浏览器打开 `https://sz.jd.com/szweb/sz/view/viewflow/flowPathDetailsNew.html`
2. F12 → Sources → 搜索 `commons-a5562705.js` 或 `gzip` 关键字
3. 找到盐值字符串（通常是 16 位字符）
4. 写到 `config/config.xlsx` 的 `USER_MNP_SALT` 字段
5. 验证：跑任一商智业务 → 不报 -407 即通过

⚠️ 这个工具 `maintain.py` 当前不做盐值检测**（太复杂），靠业务运行结果兜底。

### 3.7 🟡 UUID 前缀（项目1）

**过期周期**：不定期

**症状**：项目1（搜索/推荐/购物车）返回 `status=-407`

**抓取流程**：
1. 浏览器 F12 → Sources → 搜索项目1相关的 JS 文件
2. 找 UUID 生成逻辑（通常是 `prefix + 随机数`）
3. 提取 prefix（通常是 22 字符 hex）
4. 写到 `main.py` 的 `UUID_PREFIX` 类常量
5. 重启脚本生效

⚠️ 项目4-13 已改用完全随机 UUID，不依赖 prefix。

## 四、影刀 RPA 配置指南（用户决策 2026-08-11）

影刀已有抓 Cookie 流程。**当前流程评估**：

### 4.1 你当前的流程（截图分析）

```
1. 打开网页（在 Microsoft Edge 浏览器中新建标签页 https://sz.jd.com/sz/view/dealAnalysis/dealSummary）
2. 跳转至新网址（将网页对象保存到 web_page，网页加载超时后终止流程）
3. 保存 Cookie（将 web_page 中的 Cookie 和 local_storage 信息保存至文件 D:\tmp\cookie\xiazai.cookie.json）
4. 关闭网页（关闭网页 web_page）
```

### 4.2 当前流程评估

| 维度 | 现状 | 评分 | 备注 |
|---|---|---|---|
| **流程长度** | 4 步 | ✅ 极简 | 抓 Cookie 最少必要步骤 |
| **目标域** | sz.jd.com（**dealAnalysis/dealSummary**） | ⚠️ **不对** | 这是**商智-交易分析**页，不是**流量来源详情页**！项目1/4/5/6/13 用的是 szgateway.jd.com 域，但 sz.jd.com 域 Cookie 通用（共享 pin + flash + 3AB9D23F7A4B3CSS 等核心字段） |
| **保存路径** | `D:\tmp\cookie\xiazai.cookie.json` | ❌ **路径不对** | 应该是 `config\cookie.txt`（单行字符串格式） |
| **保存格式** | `.json` | ❌ **格式不对** | 应该是**单行 Cookie 字符串**（项目代码用 `f.read().strip()` 直接当 HTTP Cookie 头用） |
| **目标 Cookie 域** | 仅 sz.jd.com | ❌ **不够** | 还需要：① jm_cookie.txt（京麦 .shop.jd.com 域）② jzt_cookie.txt（京准通 jzt-api.jd.com 域）③ imap_config.ini auth_code（QQ 邮箱独立） |
| **有效性验证** | 无 | ⚠️ 弱 | 应该跑 `python maintain.py --live` 验证 Cookie 真能用 |

### 4.3 流程结论

**当前流程只能拿到「商智 sz.jd.com 域 Cookie 的 JSON 格式」**，需要 3 处修正才能给项目代码用：

1. **保存路径**：`D:\tmp\cookie\xiazai.cookie.json` → `config\cookie.txt`（与代码期望一致）
2. **保存格式**：JSON → **单行 Cookie 字符串**（把 JSON 里所有 cookie 字段拼接成 `name1=value1; name2=value2; ...` 格式）
3. **新增抓取项**：除了商智，还要抓 ② 京麦 Cookie（`config\jm_cookie.txt`）和 ③ 京准通 Cookie（`config\jzt_cookie.txt`）
