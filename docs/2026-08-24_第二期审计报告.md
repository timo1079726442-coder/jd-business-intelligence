## 二、H 高危项（15 项，**必看**）

### A. 多店并发数据污染（3 项，最危险）

#### H-10 AuthLoader 单例 5 秒缓存 cache_key 不含 shop_id
- **文件**：[auth_loader.py:134-160](auth_loader.py#L134) + [rpa_run.py:254](rpa_run.py#L254) + [module1.py:143](module1.py#L143)
- **风险**：`AuthLoader` 是单例，`_cache` 字典的 cache_key 形如 `f"cookie_str:{biz_type}:{check_expire}"` 不含 shop_id。影刀 60 秒店间冷却结束后切店，前 5 秒（`_cache_ttl=5`）仍命中上店 Cookie → **MIYO 业务用 FYA 鉴权发请求**。
- **修复**：
  ```python
  # auth_loader.py
  cache_key = f"{self.shop_id}:cookie_str:{biz_type}:{check_expire}"  # 加 shop_id 前缀
  ```
  或切店入口显式 `AuthLoader().clear_cache()`。

#### H-11 rpa_run.py / module1.py 未 set SHOP_PIN → DB DELETE 错位
- **文件**：[rpa_run.py:254](rpa_run.py#L254) + [module1.py:143](module1.py#L143) + [db_utils.py:444-461](db_utils.py#L444)
- **风险**：`rpa_run.py:run_shop` 只 set `SHOP_ID`，没 set `SHOP_PIN`。而 `db_utils.upsert_df` 的 fallback 用 `shop_id.replace("箱包旗舰店", "")="FYA"`，但 config 实际是 `shop_pin="FYA8888"` → DELETE 找不到记录 → **数据堆积 + UNIQUE 冲突**。
- **修复**：
  ```python
  # rpa_run.py:run_shop + module1.py:main 入口
  from runtime_config import get_shop_pin
  os.environ["SHOP_PIN"] = get_shop_pin()
  ```
  或 `db_utils.upsert_df` 去掉 fallback，直接 SystemExit。

#### H-12 `_last_request_time` 类属性 × 多进程并发限流碰撞
- **文件**：[main.py:537](main.py#L537) + [main.py:759-765](main.py#L759) + [main.py:822](main.py#L822)
- **风险**：`_last_request_time = 0` 是类属性，单进程顺序跑 3 店没事（每店间 60 秒冷却）。但**影刀 RPA 凌晨并发跑 3 个 subprocess**，每个进程独立 `_last_request_time=0` → 3 个进程同时打京东 → 触发 601 限流。
- **修复**：
  1. 改为磁盘/SQLite 持久化全局锁（跨进程同步）
  2. 或在 `rpa_run.py` 入口加 `fcntl` 文件锁（Windows 用 `msvcrt.locking`）
  3. 当前方案：影刀串行调度3店（每店独立 process）→ 单进程内 cooldown 已够，但缺乏"并发调度"风控保护

### C. 错误处理 / 资源泄漏（3 项）

#### H-18 IMAP 连接泄漏（fetch_password_from_imap 整段）
- **文件**：[main.py:7834-7970](main.py#L7834)
- **代码片段**：
  ```python
  while _time.time() < deadline:
      attempt += 1
      try:
          mail = imaplib.IMAP4_SSL(...)
          mail.login(...)
          # 搜索/解析/解码邮件...
          if password:
              mail.logout()
              return password
          mail.logout()
      except imaplib.IMAP4.error as e:
          raise RuntimeError(...)   # ← mail.logout() 未调！
      except Exception as e:
          print(...)                # ← mail.logout() 未调！
  ```
- **风险**：在 `mail.search / fetch / decode_header` 任何一处抛异常，`mail.logout()` 都不会被调用。**5 分钟超时 × N 次失败可导致 QQ IMAP 服务端拒绝新连接**。
- **修复**：
  ```python
  mail = None
  try:
      mail = imaplib.IMAP4_SSL(...)
      ...
      return password
  finally:
      if mail is not None:
          try: mail.logout()
          except Exception: pass
  ```

- **文件**：[main.py:3204](main.py#L3204) / [main.py:3235](main.py#L3235) / [main.py:4042](main.py#L4042) / [main.py:4843](main.py#L4843) / [main.py:5217](main.py#L5217) / [main.py:5727](main.py#L5727) / [main.py:6115](main.py#L6115)
- **代码片段**：
  ```python
  resp = self.session.post(url, json=payload, timeout=30)   # ← 无 try/except
  ```

- **风险**：JZT 5 个业务类（快车订单、全站营销3 个、JZT list）所有 `session.post/get` 都没 try-except。网络抖动/DNS 失败/SSL 错误会冒泡为原始 `requests.exceptions.RequestException`，用户看到的不是 Cookie/风控类错误，无法快速定位。

#### H-20 JZT 601 限流用 RuntimeError 而非 RiskControlError
- **文件**：[main.py:3153](main.py#L3153) / [main.py:4010](main.py#L4010) / [main.py:4818](main.py#L4818) / [main.py:5141](main.py#L5141) / [main.py:5655](main.py#L5655)+

  ```python
  if code == 601:
  ```

- **修复**：JZT 5 处 `_handle_response` 的 601 分支统一改为 `raise RiskControlError(...)`，与项目4/5/6 对齐。

### D. 安全风险 - Cookie/h5st 泄漏（2 项）

#### H-21 auth_loader.py CLI 调试直接打印 Cookie 前 80 字符
- **文件**：[auth_loader.py:922](auth_loader.py#L922)
- **代码片段**：
  ```python
  cookie = auth.get_cookie_str(biz_type)
  print(f"\n✅ Cookie 字符串（前 80 字符）：{cookie[:80]}...")
  ```
- **风险**：Cookie 前 80 字符通常含 `pin=xxx; thor=xxx; ...` 等敏感字段。**进程列表 / 终端历史 / 日志重定向都可能曝光**。
- **修复**：
  ```python
  print(f"\n✅ Cookie 长度：{len(cookie)} 字节（已脱敏）")
  print(f"   字段数：{len(cookie.split(';'))} 个")
  if os.environ.get("DEBUG_AUTH") == "1":
      print(f"   [DEBUG] cookie[:80]={cookie[:80]!r}")
  ```

#### H-22 auth_loader.py / main.py 业务类打印 h5st 前 30 字符
- **文件**：[auth_loader.py:929](auth_loader.py#L929) + [main.py:6969](main.py#L6969) / [main.py:8537](main.py#L8537)
- **代码片段**：
  ```python
  # auth_loader.py:929
  print(f"\n✅ h5st（前 30 字符）：{h5st[:30]}...")
  # main.py:6969/8537
  print(f"   Headers(关键): dsm-eid={headers['dsm-eid'][:30]}..., h5st={self.h5st[:30]}...")
  ```
- **风险**：h5st 是京东签名 token，前 30 字符含时间戳段，泄漏后理论上可被滥用。每次跑业务都会触发，**可能进入 stdout 重定向文件或 docker logs**。
- **修复**：
  ```python
  print(f"   h5st={self.h5st[:6]}***{self.h5st[-6:]}...（共 {len(self.h5st)} 字符）")
  ```

## 六、运行时配置加载器（runtime_config.py）扩展建议

### 6.1 当前 API（4 个核心 getter）

| 函数 | 数据源 |
|---|---|
| `get_shop_id()` | `os.environ["SHOP_ID"]` → SystemExit |
| `get_shop_pin()` | `SHOP_PIN` → config.xlsx「店铺账号」→ SystemExit |
| `get_app_id(biz)` | `APP_ID_<BIZ>` → `APP_ID` → config.xlsx → SystemExit |
| `get_sign_salt()` | config.xlsx「全局/sign_salt」→ 老 key → SystemExit |

### 6.2 建议新增 getter（v2.0）

| 新增 getter | 来源 | 对应 finding |
|---|---|---|
| `get_jzt_pin_options(shop_id) → str` | config.xlsx「店铺清单」第 4 列 | H-16 |
| `get_kuaiche_checksum() → int` | config.xlsx「京准通快车/检查码」 | M-07 |
| `get_window_days(batch) → int` | config.xlsx「全局/批次天数」 | M-11 |
| `get_shop_interval_seconds() → int` | config.xlsx「全局/shop_interval_seconds」 | M-12 |
| `get_export_type(biz_key) → int` | config.xlsx「京麦接口/export_type_*」 | L-13 |
| `get_user_agents() → List[Tuple[str, str]]` | config.xlsx「全局配置/UA_列表」 | L-11 |
| `get_site_id() → str` | config.xlsx「京准通/siteId」 | M-16 |
| `get_limit(biz_key) → int` | config.xlsx「全局/limit」 | L-15 |
| `get_origin_referer(biz) → Tuple[str, str]` | config.xlsx「接口域/路径」 | L-12 |
| `get_master_row_threshold() / get_master_cleanup_days()` | config.xlsx「Excel总表」 | M-13 |

### 6.3 扩展原则

- **禁止新建多个加载器**，扩展现有 `runtime_config.py`（与 H-04/H-05/H-06 风格一致）
- 所有 getter 必须从 config.xlsx 读取，**读取不到 → SystemExit**（不静默兜底）
- 唯一例外：`_FALLBACK_*` 这种"店铺/业务清单本身缺失"的兜底场景（已有 WARN 机制）
